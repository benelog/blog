# 이 저장소에서 자주 걸리는 검증 유형

과거 검증에서 실제로 나온 유형이다. 새 글을 볼 때 같은 유형이 있는지 먼저 훑는다.

## 예제 하나를 언어 전체의 규칙으로 확대

swap 예제에서 `&a`를 명시했다고 "그 언어는 호출 지점에 표시가 있어야 호출자 변수를 바꾼다"로 일반화하면
Go의 포인터 수신자 메서드(`n.Set()`가 `(&n).Set()`으로 해석됨)나 Rust의 메서드 호출 자동 대여가 반례가 된다.
비교 표와 정리 절은 특히 이런 확대가 일어나기 쉬운 자리다. 표의 각 칸이 예제가 아니라 언어 사양에 근거하는지 본다.

## 타입 규칙에 예외 조항이 있는데 표에는 원칙만 적음

Ada는 elementary type이 by-copy지만 `aliased` 파라미터는 타입과 관계없이 by-reference다(ARM 6.2).
"X 타입이면 항상 Y 방식"이라는 문장을 보면 사양의 예외 조항을 찾는다.

## 버전 조건을 잘못 잡은 구현 설명

"glibc 2.24 미만에서는 posix_spawn이 fork를 쓴다" 같은 문장은 실제로는 2.4~2.23이 인자에 따라 vfork를 고르는 식으로 더 세분화돼 있었다.
버전 경계가 나오면 해당 버전의 소스나 릴리스 노트를 직접 본다.

## "제약 없이", "항상", "고정" 같은 단정

멀티스레드 fork 뒤 async-signal-safe 제약, 파이프 크기, JDK 기본 문자 집합(COMPAT 설정)처럼 예외가 있는 곳에 단정이 붙어 있으면 근거를 찾는다.

## 표준 문서가 쓰지 않는 용어를 표준의 용어처럼 서술

C++ 표준은 call by reference라는 말을 쓰지 않는다. "표준이 X를 Y라고 부른다"는 문장은 표준 원문에서 그 용어를 검색해 확인한다.

## 링크 표시 문구와 렌더링

인용 자체는 맞아도 AsciiDoc 렌더링이 깨져 독자에게 다르게 보이는 경우가 있다.
`C++`가 한 문단에 짝수 번 나오면 `++`가 패스스루로 처리되어 사라지므로 `{cpp}` 속성을 쓴다.
링크 표시 문구 안의 백틱은 코드로 렌더링되지 않는다. 사실 검증 범위는 아니지만 발견하면 기록의 "한계" 아래에 별도 항목으로 적는다.

## 인용문 검증 요령

* WebFetch가 긴 사양 페이지를 자르면 `curl -sL <url> -o page.html` 후 python으로 태그를 벗기고 문장을 검색한다.
* PDF 표준 초안(C의 N1570 등)은 HTML 미러(port70.net 등)에서 각주 번호까지 대조한다.
* 각주 번호와 절 번호는 판본에 따라 달라지므로 어느 초안(N1570, N4950 등)인지 기록에 적는다.
