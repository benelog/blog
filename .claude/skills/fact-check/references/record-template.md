# 검증 기록 템플릿

파일 경로: `fact-checks/<slug>-<YYYY-MM-DD>.md`

```markdown
# <글 제목> 사실 관계 검증 — <YYYY-MM-DD>

- 대상: [<slug>.adoc](../src/content/<slug>.adoc)
- 검토 기준 커밋: `<40자 해시>` (작업 트리 변경이 포함되면 "미커밋 변경 포함"이라고 적는다)
- 이전 기록: [<날짜> 검증](<이전 파일>.md) (없으면 "없음")
- 범위: <어느 절, 어떤 종류의 주장을 봤는지>
- 방법: Codex 적대적 리뷰 후 Claude가 1차 출처로 재검증. <재현 실행 여부>
- 결과: **우선 수정할 사항 N건, 표현을 보완할 사항 M건.** <핵심 결론이 타당한지 한 문장>
- 반영 상태: **미반영.** (반영 후 커밋 해시를 적고 항목마다 "반영 완료"를 표시한다)
- 아래 행 번호는 위 커밋 기준이다.

## 우선 수정할 사항

### 1. <무엇이 잘못됐는지 한 문장>

**위치: 본문 NNN행.** <현재 본문이 어떻게 서술하는지>

<왜 틀렸는지, 어떤 경우에 반례가 생기는지>

수정 제안:

> <본문에 그대로 넣을 수 있는 문장>

근거: [<출처 이름과 절>](<URL>).

<소스 대조 판정인지 실행 확인인지>

## 표현을 보완할 사항

### 1. <과도한 일반화 등>

(위와 같은 구조)

## 확인한 사항

| 주장 | 판정 | 근거 |
|---|---|---|
| <본문 주장 요약> | **확인.** <어떻게 확인했는지 짧게> | [<출처>](<URL>) |
| <본문 주장 요약> | **확인.** Codex 지적, 재검증 결과 기각. <이유> | [<출처>](<URL>) |

## 한계

- <확정하지 못한 항목과 이유. 예: 원문 접근 불가, 실행 환경 없음>
```

머리말의 "결과" 줄은 건수와 핵심 결론을 함께 적는다. 수정 사항이 없으면 "**수정할 사항 없음.**"으로 쓰고 확인한 사항 표는 남긴다.
